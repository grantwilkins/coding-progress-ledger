## 1. Batch plan

Per TASKS.md U4. Each batch ends with a rebuild + profile pass before
the next begins.

| batch | runs | task mix | gate after batch |
|---|---:|---|---|
| Batch 0 (pilot) | 10 | 5 internal scaffolds + 5 TB2 tasks (1 per major category) | confirm sidecar protocol; confirm dynamics labels fire on internal tasks; check infrastructure-failure rate < 10% |
| Batch 1 | 30 | 15 TB2 + 5 original-TB-easy + 10 internal | check pass rate ∈ [0.30, 0.70]; if not, **resample tasks** per U2 § "What to do if the first batch is all successes" |
| Batch 2 | 30 | 15 TB2 + 15 internal | shape diversity: confirm ≥ 5 progress drops, ≥ 3 validation_new_work in the 60 runs collected so far |
| Batch 3 | 30 | 30 TB2 (fill missing categories/failure modes) | confirm category mix is within ±10 percentage points of policy; confirm ≥ 25 failures total |
| reserve | 20 | targeted resampling to hit shape goals | only if shape-goal floors not hit by end of Batch 3 |

Final target: 100+ runs (Batch 0 + 1 + 2 + 3 = 100; reserve as needed).

Each run is a single TB harness invocation. Per arm, each task is run
exactly once. No retries except the single re-run allowed for malformed
ledger output (per U2).

## 2. Per-batch loop

```text
for batch in [0, 1, 2, 3, reserve]:
    1. select tasks per batch plan + sampling policy
    2. for each task, for each arm in [A, B]:
         tb run --agent terminus \
                --model <arm.model> \
                --task <task_id> \
                --max-agent-timeout-sec <arm.timeout> \
                --max-iter <arm.max_iter>
       collect: ledger.jsonl, terminal_output.log, verifier_output.txt,
                live_instrumentation.json, run_manifest.json
    3. uv run python scripts/build_checkpoints.py --source tb_live_v2
    4. uv run python -c "
       from coding_estimator.labels.build import write_combined_labels
       from pathlib import Path
       write_combined_labels(Path('datasets'))
       "
    5. profile:
       - pass rate this batch
       - cumulative pass rate
       - shape distribution this batch (dynamics + shapes labels)
       - category mix
       - infrastructure-failure rate (runs with malformed ledger,
         retried once, still failed)
    6. write reports/tb_live_v2_batch_<n>_profile.md (autogenerated)
    7. gate decision: continue / resample harder / resample easier /
       stop (if budget exhausted) — per U2 anti-tuning rules
```

## 4. Stop conditions

Stop and freeze the corpus if **any** holds:

```text
- 100 runs completed and shape goals (U2) all met.
- After Batch 3 + reserve: shape goals are at floor (15 progress drops,
  10 validation_new_work, 10 stuck/blocked, 5 high-progress fail,
  5 low-progress success).
- Cost cap reached (see § 5).
- Infrastructure-failure rate exceeds 25% in any single batch (suggests
  the harness or sidecar bridge is broken; fix before continuing).
```

Do **not** stop early just because pass rate looks good. The
corpus needs failure variety, not just failure count.

## 5. Cost discipline

Approximate budget envelope, sized for U4 sign-off before kickoff:

```text
top-tier model run @ 90 s wall + degraded budget
  ≈ 5 000 input tokens + 10 000 output tokens per run
  ≈ Arm A 75 runs × $X / 1k tokens

mid-tier model run
  ≈ similar
  ≈ Arm B 75 runs × $Y / 1k tokens

infrastructure
  Docker compute is local; no GPU needed (excluded by U2)
```

Estimate the dollar cost for both arms before Batch 0 and document in
`reports/tb_live_v2_cost_estimate.md`. If the estimate exceeds the
project budget, drop Arm B (per U2 fallback).

## 6. Risks specific to execution

- **Verifier flakiness.** Some TB2 tasks pass intermittently due to
  network or timing. For each task that fails the pre-flight oracle
  smoke (i.e., the published `solution.sh` does not pass on a fresh
  pull), exclude the task from `tb_live_v2` and document in the
  collection manifest.
- **Sidecar bridge drift.** If TB harness output schema changes between
  releases, the bridge to `ledger.jsonl` breaks silently. Pin the
  `terminal-bench` package version in `pyproject.toml` and record the
  version in the collection manifest.
- **Run leakage between arms.** A task that passed in Arm A may have
  cached state if Docker volumes persist. Use ephemeral volumes; verify
  by inspecting `tb run --help` for the volume policy.
- **Outcome-tuning temptation.** When pass rate drifts outside band,
  the temptation is to swap models. U2 forbids this. The enforcement
  hook is the protocol-changes log: every config change must be
  recorded with a rationale.
