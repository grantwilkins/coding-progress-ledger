\section{Introduction}

LLM serving increasingly manages persistent sessions rather than independent requests. A coding assistant, browser agent, or research copilot issues many model calls over minutes or hours, each depending on prior context, tool outputs, and intermediate state~\cite{yang2024sweagent,kwa2026measuring}. When a source cluster must shed load, whether for maintenance, failure, traffic shifting, or a power-shed command, the system must decide where future requests run and how their serving state is rebuilt at the destination. Prefill and decode stress different resources~\cite{zhong2024distserve,patel2024splitwise}, and the KV cache is large and central to serving performance~\cite{kwon2023efficient,lmcache}. Session migration therefore becomes a resource-allocation problem over compute, bandwidth, cache state, and time.

\textbf{Single-session case.} The simplest case is a single-session compute-communication tradeoff. A session can resume by transmitting its context and recomputing KV state through prefill, or by transmitting the KV cache and avoiding recomputation. Figure~\ref{fig:migration-ratio} plots this boundary for several models as inter-site bandwidth varies. Replay is preferable when bandwidth is limited or prefill is fast. KV transfer wins when bandwidth is high or prefill is expensive. For context length $T$, context size $\beta T$, KV size $\eta T$, prefill rate $\rho$, and bandwidth $\lambda$, replay is faster when
\[
    \underbrace{\frac{\beta T}{\lambda} + \frac{T}{\rho}}_{\text{context transfer and prefill}}
    <
    \underbrace{\frac{\eta T}{\lambda}}_{\text{KV transfer}},
\]
with crossover
\[
    \lambda^\star = \rho(\eta-\beta).
\]
This calculation identifies the basic parameters, but it only describes an isolated session.

The boundary also moves with context length and bandwidth. We show this for Qwen3-235B in Figure~\ref{fig:context-ratio}, where longer contexts and higher bandwidths favor KV transfer and shorter contexts and lower bandwidths favor replay. The nearly piecewise-linear shape comes from attention. KV cache size grows linearly with context length, while prefill time grows superlinearly because attention is quadratic, and that gap sets a sharp boundary in both context length and bandwidth. The boundary is the context length where replay (prefill) time meets KV-transfer time,
\[
\underbrace{\frac{2AT+\kappa T^2}{F}}_{\text{prefill (replay) time}}\;=\;\underbrace{\frac{\eta T}{\lambda}}_{\text{KV-transfer time}},
\]
with $A$ the active parameter count, $\kappa$ the per-token attention cost (from layers, heads, and head dimension), $F$ the device throughput, $\eta$ the KV bytes per token, and $\lambda$ the bandwidth. The feed-forward term $2AT$ is linear in $T$, while the attention term $\kappa T^2$ makes prefill superlinear, so the constant rate $\rho$ used above is really $F/(2A+\kappa T)$ and slips as the context grows. Cancelling $T$, the crossover sits at
\[
T^\star=\frac{1}{\kappa}\Big(\frac{F\eta}{\lambda}-2A\Big),
\]
which shrinks as bandwidth $\lambda$ rises, pushing the boundary toward shorter contexts exactly as Fig.~\ref{fig:context-ratio} shows.


\textbf{Going to many sites.} A site-level shed couples many sessions through shared destination resources. Replaying everything overloads prefill, and transferring all KV state congests the inter-site links. The policy problem is to allocate sessions across destinations and reconstruction actions while respecting bandwidth, prefill capacity, state-ingest capacity, and the required source-load reduction.

This project studies a convex relaxation of that allocation problem with a tool we call \emph{Queue-Haul}. We group sessions into classes by model and context length. For each class the decision is the fractional number of jobs sent to each destination under each of two reconstruction actions, \emph{replay} and \emph{state transfer}, plus a \emph{stranded} count for jobs that miss the deadline. Replay is light on bandwidth but loads prefill. State transfer loads bandwidth and ingest but skips prefill. Both add reconstruction delay and deadline risk.

Rather than collapse the competing goals into one weighted cost, we solve a short \emph{ordered} stack of convex programs. The stages first allocate the migration fairly, then minimize peak resource pressure, and finally refine the worst-class rebuild cost and cross-class fairness. The result is a continuous relaxation of the discrete placement problem. It does not model online scheduling or queueing, but it exposes the resource tradeoffs and gives a principled routing model. 

We solve this stack exactly with CVXPY and then study the dual of the resource-pressure problem, where the congestion prices emerge. The dual yields prices that we put to work in two ways. One is an envelope-theorem sensitivity check. The other runs subgradient, mirror-descent, and ADMM solvers against the same dual. Our central finding is that the exact solve recovers sensible replay and state-transfer structure together with interpretable congestion prices.
