# Queue-haul drift audit

Updated 2026-05-25 after local review plus four critic subagents. This file is
the current formulation/implementation drift ledger; old entries not repeated
below should be treated as stale.

## Blocking model drift

1. Replay prefill skips on raw-context locality.
   `src/coefficients.py:52-53` uses
   `b_net[REPLAY]=beta*T*(1-h_ctx)` and
   `b_prefill[REPLAY]=T*(1-h_ctx)`. The first term is plausible; the second
   should depend on KV residency, `T*(1-h_kv)`. Current tests encode the wrong
   behavior in `tests/test_objective.py`.

2. STATE is network-only.
   `src/coefficients.py:48-57` sets `b_net[STATE]=eta*T*(1-h_kv)` but leaves
   `b_prefill[STATE]=0` and `R0[STATE]=b_net/lambda`. `ProblemData` has only
   network and prefill capacity fields (`src/problem.py:18-23`), so the
   journal's third pressure, state ingest/decode, is absent. The simulator also
   completes STATE after network only (`src/queueing.py:206-219`).

3. `R0` mixes single-link network with aggregate-fleet prefill.
   `lambda_Bps` is a per-destination link (`src/problem.py:172`), but
   `rho_prefill=model.prefill_tok_s*gpu_count` (`src/problem.py:173`). Then
   one request's replay work is divided by aggregate GPU prefill in
   `src/coefficients.py:56`. For GLM-5, 25 Gb/s, `T=100k`, and 72 GPUs:
   `R0_REPLAY ~= 0.167s`, `R0_STATE ~= 2.88s`; per-GPU replay is `~=12.05s`.
   This is load-bearing because `q=R0` (`src/coefficients.py:58`), the objective
   sums `q*x` (`src/objective.py:15`), and greedy baselines rank by `q`
   (`src/baselines.py:68`). `transition-coupled` patches generated workloads to
   `gpu_count=[1,1,1]` (`src/problem.py:159-160`), but default generated runs do
   not.

4. The LP does not generally recover `lambda* = rho(eta-beta)`.
   `src/catalog.py:15-16` and the H3 helper compute the single-request formula
   directly, and an isolated test recovers it with manually supplied per-GPU
   `rho`. Default `make_problem()` shifts the LP crossover by `gpu_count`, so
   report claims based on default LP runs are unit-inconsistent until #3 is
   fixed.

## Formulation drift

1. Shared-prefix amortization is absent.
   The workload state is only `T,d,deadline_s,h_ctx,h_kv`
   (`src/workload.py:8-14`). Aggregation averages full `T`
   (`src/workload.py:213-226`). There is no `T_s/T_p`, prefix class, block set,
   or once-per-shared-prefix cost, so every moved class member pays full
   `eta*T` or replay `T`.

2. Resident-state dynamics are static.
   `h_ctx` and `h_kv` are sampled once (`src/workload.py:29-35`) and consumed as
   fixed coefficients (`src/coefficients.py:45-46`). The paper equation
   `R_k <- R_k union B_j` is not modeled; routing one request never makes later
   overlapping requests cheaper.

3. The action space is collapsed.
   Code has `("replay", "state")` plus the stay column
   (`src/coefficients.py:9-11`). Local prefix reuse, cross-instance reuse, and
   state materialization are hidden inside exogenous hit rates. Live duplicate,
   relay-start, and per-turn agent state are out of scope unless explicitly
   added.

4. "Online" baselines are fixed-batch passes.
   `_solve_online` walks a static EDF request list and updates local loads
   (`src/baselines.py:89-137`). It is not an event-time router with new
   arrivals, dynamic background traffic, or resident-state updates.

## Convex relaxation drift

1. Deadline LP feasibility is necessary, not sufficient.
   Hard deadline constraints cap cumulative network and prefill work separately
   by destination/deadline (`src/cvxpy_solver.py:106-118`). The queue simulator
   enforces serial replay service, network then prefill (`src/queueing.py:191-219`).
   Counterexample: two replay jobs with per-job network service `D/2` and
   prefill service `D/2` satisfy both LP caps at deadline `D`; the second job
   completes at `1.5D`.

2. Post-solve row renormalization erases the solver margin.
   All CVXPY solvers rescale `y.value` after solve
   (`src/cvxpy_solver.py:67,131,221`). The modeled constraint is
   `u <= 1-eps`, but validation only checks `u < 1` (`src/metrics.py:175-177`).
   The returned allocation can lose the strict certificate even when it remains
   inside the barrier domain.

3. Soft-deadline penalties weaken as constraint count grows.
   Overrun cost is divided by `2*K*|deadlines|` (`src/cvxpy_solver.py:199-204`).
   Adding destinations or deadline strata lowers each violation's marginal
   weight unless weights are retuned.

4. Slater/interior feasibility is not checked.
   `make_problem()` builds capacities and retained targets without proving a
   strict interior (`src/problem.py:106-179`). Mirror descent separately builds a
   capacity-interior start and a greedy target-feasible point
   (`src/mirror_descent.py:29-81`); this is not a proof that the paper's
   relaxation has Slater points for all generated cases.

5. Fractional routing is a real relaxation gap.
   CVXPY routes continuous class fractions (`src/cvxpy_solver.py:31`); execution
   rounds later (`src/queueing.py:72-96`) and uses a greedy fallback for large
   state spaces (`src/queueing.py:409-430`). A large class near a deadline cap
   can violate schedule constraints after rounding by an `Omega(max_g b_g/(rate*D))`
   term.

6. Mirror descent should be scoped narrowly.
   It is exponentiated gradient with scalar dual bisection only for the
   retained-prefill constraint (`src/mirror_descent.py:128-183`). It is a
   preliminary method for the plain fixed-load barrier problem, not a first-order
   solver for the deadline-aware or soft-deadline formulations.

7. `SolverResult.objective` is current, but easy to misuse.
   The old drift note that objectives differ across CVXPY solvers is stale:
   all three solvers now store `objective(problem, coeffs, y)` in `.objective`
   (`src/cvxpy_solver.py:68,136,236`). Native solver objectives are different
   and live only in diagnostics, so solver-specific objective comparisons still
   need explicit fields.

## Queueing and experiment drift

1. Default retained shed is partial, not evacuation.
   `retained_prefill_fraction=0.4` by default (`src/problem.py:109`), and the
   stay column allows unmoved work. Unless a run sets or sweeps the fraction to
   `1.0`, "evacuation" means "move enough retained prefill to meet a target",
   not "drain all source work".

2. Arrival pacing is mixed.
   Core queue evaluation defaults to uniform release over `drain_window_s`
   (`src/queueing.py:99-105,559-607`). The retained-state frontier currently
   uses burst-at-zero via `QUEUE_RELEASE_SPAN_S=0.0`
   (`experiments/run_retained_state_frontier.py:65-66,251-258`). Report which
   pacing each figure uses.

3. SAFE definitions still diverge.
   Retained frontier uses strict target, absolute deadline, pressure, and drain
   checks (`experiments/run_retained_state_frontier.py:362-370`). Plotting uses
   the same strict fields (`experiments/plot_queue_centered.py:565-573`).
   Queue-failure diagnostics omit pressure and drain
   (`experiments/run_queue_failure_diagnostics.py:691-696`). Report/network
   scripts include pressure and drain, but use release-relative deadline metrics
   (`experiments/run_report_experiments.py:461-469`,
   `experiments/run_network_bandwidth_tradeoff.py:122-130`).

4. Frontier search assumes near-monotonicity.
   The retained frontier binary-searches safe fraction
   (`experiments/run_retained_state_frontier.py:203-210`) and samples local
   offsets plus one stress point (`experiments/run_retained_state_frontier.py:211-215`).
   This catches small local cliffs but can miss nonlocal safe islands caused by
   rounding, EDF bands, or solver action changes.

5. Baseline comparisons are not deadline-matrix fair.
   Least-loaded ranks by max utilization (`src/baselines.py:117`). Online queue
   greedy sees EDF order and current backlog, but not the full due-by-deadline
   load matrix (`src/baselines.py:100-118`). Deadline CVXPY sees cumulative
   deadline constraints for every destination (`src/cvxpy_solver.py:106-118`).
   Do not claim general deadline superiority without a deadline-aware online
   baseline.

6. Seed coverage is improved but still thin.
   Defaults remain seed 7 with 10k jobs and 48 classes (`src/evaluation.py:12-18,
   38-52`). The retained frontier CLI uses seeds `0..15`
   (`experiments/run_retained_state_frontier.py:65,544-550`) and plots means/std,
   but report-facing defaults and other sweeps are still point estimates unless
   rerun over seeds. Use median and IQR for headline numbers.

7. Fleet dynamics are static.
   `make_problem()` samples one fixed workload (`src/problem.py:126-132`).
   Background traffic is fixed load fractions (`src/problem.py:141-177`), and
   queue records come only from the chosen allocation (`src/queueing.py:447-500`).
   No new background arrivals, cross-shed coupling, or destination power dynamics
   are modeled.

## Documentation and artifact drift

1. README "manifest" wording overstates the implementation.
   `README.md` lists `h4_state_manifest_heatmap`, but the plot labels only class
   `T`, deadline, max `h_ctx`, and max `h_kv`
   (`experiments/plot_queue_centered.py:397-408`). There are no manifest fields,
   block hashes, or compatibility IDs.

2. Generated artifacts are diagnostic, not evidence by themselves.
   CSVs under `outputs/sweep/generated_*` are committed and can include unsafe,
   failed, or unresolved claim rows. Regenerate with the exact workload label and
   seed policy before report use.

## Stale prior notes

- "SAFE can mean overloaded" is stale for the current retained frontier; strict
  pressure and drain checks are now present.
- "Deadline-aware CVXPY can return success below target" is stale; it now
  constrains and asserts the retained-prefill target
  (`src/cvxpy_solver.py:88-90,253-254`).
- "Invalid queue actions silently pass" is stale; `_paced_records` hard-fails
  unknown actions (`src/queueing.py:572-574`).
- "ProblemData is frozen but stores mutable arrays" is stale; array fields are
  copied and marked read-only (`src/problem.py:82-86`).

## Remediation order

1. Fix replay prefill locality: `h_ctx -> h_kv` for `b_prefill[REPLAY]`.
2. Add state ingest/decode pressure, preferably as a separate capacity bucket.
3. Make `lambda` and `rho` denominators consistent, then test LP recovery of
   `lambda* = rho(eta-beta)` in the single-class uncongested limit.
4. Rename partial-shed metrics or set evacuation experiments to fraction `1.0`.
5. Unify SAFE definitions and explicitly label burst versus paced arrivals.
6. Add a deadline-aware online baseline.
7. Run multi-seed sweeps with median/IQR before using headline numbers.
